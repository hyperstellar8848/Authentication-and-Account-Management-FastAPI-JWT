# تمرین ۳: سیستم احراز هویت و مدیریت حساب کاربری (FastAPI + JWT)

## ۱. توضیح کلی
در این تمرین شما باید یک سیستم احراز هویت بسازید که از دو بخش اصلی تشکیل شده است:

*   **بخش API (بکند):** مجموعه‌ای از Endpointها با فریم‌ورک **FastAPI** که عملیات ثبت‌نام، ورود، خروج، مشاهده و ویرایش پروفایل، تغییر رمز عبور، بازیابی رمز عبور و مدیریت کاربران توسط ادمین را انجام می‌دهند. احراز هویت باید با **JWT** انجام شود.
*   **بخش UI (فرانت‌اند):** صفحات وب ساده با HTML/CSS که کاربر بتواند از طریق مرورگر با سیستم کار کند. انتخاب تکنولوژی فرانت‌آند کاملاً آزاد است.

### خروجی نهایی پروژه
وقتی پروژه اجرا می‌شود، یک کاربر باید بتواند:
1. وارد صفحه ثبت‌نام شود و حساب کاربری بسازد.
2. وارد صفحه ورود شود و با نام کاربری و رمز عبور وارد سیستم شود.
3. بعد از ورود، اطلاعات پروفایلش را ببیند و ویرایش کند.
4. بتواند رمز عبور خود را تغییر دهد.
5. اگر رمز خود را فراموش کرد، کد بازیابی دریافت کرده و رمز جدید تنظیم کند.
6. بتواند از سیستم خارج (Logout) شود.
7. اگر ادمین است، بتواند لیست کاربران را ببیند، اطلاعاتشان را ویرایش کند و آن‌ها را فعال/غیرفعال کند.

> **نکته:** استفاده از JWT برای احراز هویت اجباری است. انتخاب دیتابیس (SQLite، PostgreSQL و...) آزاد است. در این تمرین تمرکز اصلی روی فرانت‌اند پیشرفته نیست؛ فقط کافی است چیدمان صفحات مرتب باشد و پیام‌ها (موفقیت/خطا) به درستی نمایش داده شوند.

## ۲. مدل‌های دیتابیس

### جدول کاربران (User)
تمام اطلاعات کاربر و پروفایل در یک جدول به نام `User` نگهداری می‌شود:

| نام فیلد | نوع داده | وضعیت / پیش‌فرض | توضیح |
| :--- | :--- | :--- | :--- |
| `id` | Integer | Primary Key | خودکار تولید می‌شود |
| `username` | String | Unique / اجباری | نام کاربری |
| `email` | String | Unique / اجباری | ایمیل کاربر |
| `hashed_password` | String | اجباری | رمز عبور هش شده |
| `first_name` | String | اجباری | نام |
| `last_name` | String | اجباری | نام خانوادگی |
| `bio` | Text | اختیاری | بیوگرافی (حداکثر ۵۰۰ کاراکتر) |
| `phone_number` | String | اختیاری | شماره تلفن با فرمت `09XXXXXXXXX` |
| `date_of_birth` | Date | اختیاری | تاریخ تولد |
| `is_active` | Boolean | پیش‌فرض: `True` | وضعیت فعال بودن حساب |
| `is_admin` | Boolean | پیش‌فرض: `False` | دسترسی مدیریت |
| `created_at` | DateTime | خودکار | زمان ساخت حساب |

### جدول کد بازیابی رمز عبور (PasswordResetCode)
| نام فیلد | نوع داده | وضعیت / پیش‌فرض | توضیح |
| :--- | :--- | :--- | :--- |
| `id` | Integer | Primary Key | خودکار تولید می‌شود |
| `user_id` | Integer | ForeignKey -> `User.id` | مشخص‌کننده کاربر درخواست‌دهنده |
| `code` | String(6) | اجباری | کد ۶ رقمی تصادفی |
| `is_used` | Boolean | پیش‌فرض: `False` | وضعیت استفاده شدن کد |
| `created_at` | DateTime | خودکار | زمان تولید کد |

## ۳. فهرست Endpointها

### دسته بندی: احراز هویت (Auth)
| متد | مسیر (Endpoint) | دسترسی | توضیح |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/auth/register` | عمومی | ثبت‌نام کاربر جدید |
| `POST` | `/api/auth/login` | عمومی | ورود کاربر و دریافت توکن JWT |
| `POST` | `/api/auth/logout` | کاربران لاگین شده | خروج از حساب کاربری |

### دسته بندی: حساب کاربری (Profile)
| متد | مسیر (Endpoint) | دسترسی | توضیح |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/auth/me` | کاربران لاگین شده | مشاهده اطلاعات پروفایل خود |
| `PUT` | `/api/auth/me` | کاربران لاگین شده | ویرایش اطلاعات پروفایل خود |
| `POST` | `/api/auth/change-password` | کاربران لاگین شده | تغییر رمز عبور فعلی |

### دسته بندی: بازیابی رمز عبور (Password Recovery)
| متد | مسیر (Endpoint) | دسترسی | توضیح |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/auth/forgot-password` | عمومی | درخواست ارسال کد بازیابی |
| `POST` | `/api/auth/reset-password` | عمومی | تنظیم رمز عبور جدید با استفاده از کد |

### دسته بندی: پنل ادمین (Admin)
| متد | مسیر (Endpoint) | دسترسی | توضیح |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/admin/users` | فقط ادمین | دریافت لیست تمامی کاربران |
| `GET` | `/api/admin/users/{id}` | فقط ادمین | مشاهده جزئیات یک کاربر خاص |
| `PUT` | `/api/admin/users/{id}` | فقط ادمین | ویرایش اطلاعات یک کاربر خاص |
| `PATCH` | `/api/admin/users/{id}/toggle-active` | فقط ادمین | فعال یا غیرفعال کردن کاربر |

## ۴. چرخه بازیابی رمز عبور (توضیح عملکرد)
فرآیند بازیابی رمز عبور در دو مرحله مجزا انجام می‌شود:

### مرحله ۱: درخواست کد بازیابی
کاربر ایمیل خود را به مسیر `/api/auth/forgot-password` ارسال می‌کند. سرور یک کد ۶ رقمی تصادفی تولید کرده و آن را در جدول `PasswordResetCode` ذخیره می‌کند. برای راحتی کار در محیط تست، این کد باید در ترمینال سرور (Console) چاپ شود.

## درخواست بازیابی رمز عبور

### Request

```json
{
  "email": "ali@example.com"
}
```

### Response

```json
{
  "message": "کد بازیابی ارسال شد"
}
```

### خروجی ترمینال سرور

```text
// ===========================
// Reset code for ali@example.com: 482916
// ===========================
```

## مرحله ۲: تنظیم رمز جدید

کاربر ایمیل، کد دریافتی و رمز جدید را به `api/auth/reset-password/` ارسال می‌کند.  
سرور بررسی می‌کند:

- کد متعلق به همین کاربر باشد
- کد قبلاً استفاده نشده باشد (`is_used = False`)

در صورت موفقیت، رمز عبور تغییر کرده و `is_used = True` می‌شود.

### Request

```json
{
  "email": "ali@example.com",
  "code": "482916",
  "new_password": "NewPass123!",
  "new_password_confirm": "NewPass123!"
}
```

# ۵. اعتبارسنجی‌ها

- `email` و `username` باید یکتا باشند
- رمز عبور حداقل ۸ کاراکتر داشته باشد و کاملاً عددی نباشد
- `password` و `password_confirm` باید برابر باشند
- در تغییر رمز:
  - رمز فعلی درست باشد
  - رمز جدید با رمز قبلی متفاوت باشد
- شماره تلفن باید با فرمت زیر باشد:

```text
09XXXXXXXXX
```

- کد بازیابی:
  - منقضی نشده باشد
  - استفاده نشده باشد

# ۶. سطح دسترسی

| نقش | دسترسی |
|---|---|
| لاگین نشده | `register`, `login`, `forgot/reset password` |
| کاربر عادی | `me` (مشاهده + ویرایش)، `change-password`، `logout` |
| ادمین | همه موارد + لیست، مشاهده، ویرایش و فعال/غیرفعال کردن کاربران |
